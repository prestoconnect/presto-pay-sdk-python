# Contributing

Thanks for looking at `presto-pay-sdk-python`. This file covers building, testing and releasing the library.
For how to *use* the SDK, see [README.md](README.md).

## Building and testing

The project uses [uv](https://docs.astral.sh/uv/):

```bash
uv sync
uv run pytest                 # unit, vector, parity and loopback socket tests
uv run mypy                   # --strict over src and tests
uv run ruff check . && uv run ruff format --check .
```

CI (`.github/workflows/ci.yml`) runs the tests on Python 3.11 to 3.14. It also runs them once against the
lowest declared dependency versions, and runs a packaging job that installs the built wheel into a clean
environment.

The optional smoke test runs against the real staging gateway and needs real staging credentials. It creates
real (unpaid) payment records on every run:

```bash
PRESTOPAY_STAGING_SMOKE=1 PRESTOPAY_ENV=staging PRESTOPAY_MID=... PRESTOPAY_MRN=... \
  PRESTOPAY_PRIVATE_KEY_FILE=... PRESTOPAY_PRIVATE_KEY_PASSWORD=... PRESTOPAY_PUBLIC_KEY_FILE=... \
  uv run pytest -m staging
```

## The spec snapshot

`spec/` is a plain copy of the shared `presto-pay-spec` repository. It is not a submodule. The commit it was
copied from is recorded in `spec/.source-commit`. To update it, copy the new tree over `spec/`, update
`.source-commit`, and commit both together. `tests/test_vectors.py` fails if the spec adds a vector file that
has no test harness here.

Vectors are never generated by this SDK. If you find a gap, add the vector to `presto-pay-spec`, either hand-written or captured
from staging.

`tests/fixtures/test-merchant-legacy.p12` wraps the throwaway spec key in the same RC2-40 encryption as
Presto's onboarding keystore. It was generated with:

```bash
openssl pkcs12 -export -legacy -inkey spec/keys/test-merchant-key.pem -in spec/keys/test-merchant-cert.pem \
  -name merchant -passout pass:changeit -out tests/fixtures/test-merchant-legacy.p12
```

## Code style

- Python 3.11 language level. `mypy --strict` and `ruff` must be clean.
- No runtime dependencies beyond `cryptography` and `httpx` unless explicitly agreed.
- `presto_pay/__init__.py` is the public API. Everything under `presto_pay._core` is private.
- No code comments unless the *why* is genuinely non-obvious (a hidden constraint, a subtle invariant, or a
  workaround). Comments never cite a plan or the contract by file or section number.

## Releasing

1. Set `__version__` in `src/presto_pay/_version.py` to the release version, and move the CHANGELOG
   `Unreleased` entries under that version.
2. Commit, then push a matching tag, for example `git tag v0.1.0 && git push origin v0.1.0`.
3. The tag runs `.github/workflows/release.yml`, which verifies, builds and publishes to PyPI through Trusted
   Publishing.
4. Bump `__version__` to the next `.dev0`.
