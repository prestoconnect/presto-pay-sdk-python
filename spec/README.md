# presto-pay-spec

The Presto Pay wire contract and its test vectors, shared by every Presto Pay SDK.

- **[`wire-contract.md`](wire-contract.md)** — the protocol. Normative, language-neutral, and the only place a
  rule is written down.
- **`vectors/`** — the machine-readable form of that contract.
- **`keys/`** — a throwaway keypair for the vectors, plus Presto's staging certificate.

SDKs pin this repository at `spec/` to a reviewed commit, either as a git submodule when a remote is available
or as a checked-in snapshot that records the source commit. A contract change is a visible update in each SDK.

## Why this is a repository and not a directory in an SDK

Four SDKs implement this contract. If the vectors lived in one of them, the other three would either copy them
and drift, or depend on that language's toolchain to run their tests. Keeping them here also makes the rule that
matters enforceable:

> **Vectors are hand-written, or captured from the gateway. They are never generated by an SDK.**

An SDK that produced its own expectations would agree with itself about a bug forever. Two of the canonical
vectors are real staging captures carrying real Presto signatures — those cannot be argued with.

## Vectors

| File | Contents |
|------|----------|
| `canonical.json` | body → canonical string, or `reject` with a reason. Cases with a `signature` are real captures and must verify against `verifyWith` |
| `timestamps.json` | epoch milliseconds ↔ `ts`, plus the strings a parser must refuse |
| `signatures.json` | canonical string → Base64 signature under the throwaway key. Generated, and safe to be: see below |
| `refund-policy.json` | payment methods for which the SDK must allow a refund request; the gateway determines the outcome |

Still to be written, as the SDKs reach them: `requests.json` (operation input → wire body), `responses.json`
(status, headers, body → mapped result or error) and `webhooks.json` (body, merchant IDs, `now` → event or
error).

### Conventions

- Field names in vectors are the **wire** names. An SDK maps them to its own naming in its test harness, which
  is a small test of that mapping.
- A case supplies either `body` (a JSON object) or `bodyRaw` (exact JSON text). `bodyRaw` exists for cases an
  object literal cannot express: duplicate keys, oversized integers, a specific escaping, invalid JSON.
- `reject` is a human-readable reason, not an error code. Implementations match on the fact of rejection, not
  on the wording.

## Checking the vectors

```bash
node scripts/verify-vectors.mjs
```

This builds every canonical string per §4 of the contract, verifies the two staging captures against Presto's
certificate, verifies every `signatures.json` entry against the throwaway public key, and round-trips every
timestamp. It is a second, deliberately naive implementation of the contract that is **not** any SDK, so an SDK
bug cannot agree with it by construction.

Regenerating `signatures.json`:

```bash
node scripts/sign-vectors.mjs          # rewrite
node scripts/sign-vectors.mjs --check  # fail if stale, for CI
```

Generating these is safe where generating `canonical.json` would not be: the canonical strings are the fixed
input and only the RSA signature is computed, by a general-purpose crypto library rather than by SDK code.
PKCS#1 v1.5 is deterministic, so the output is stable and any diff means an input changed. The result matches
the OpenSSL command line byte for byte:

```bash
printf '%s' "1201:Invalid input.:false:20260924124938.038" \
  | openssl dgst -sha256 -sign keys/test-merchant-key.pem | openssl base64 -A
```

## Keys

| File | What it is |
|------|------------|
| `test-merchant-key.pem` | Throwaway RSA-2048 private key, PKCS#8, unencrypted. Signs `signatures.json` |
| `test-merchant-public.pem` | Its public key, SPKI |
| `test-merchant-cert.pem` / `.der` | A self-signed certificate over the same key, so SDKs can test certificate import in both encodings |
| `presto-staging.der` | Presto's **staging** certificate. Verifies the captured bodies in `canonical.json` |

The throwaway key is in version control on purpose and is worthless: it signs nothing but test vectors. No
merchant key, staging or otherwise, belongs here.

## Changing the contract

A rule and its vectors change in the same commit, and the commit says which gateway behaviour prompted it.
Promoting a rule from **[U]** to **[C]** means citing what confirmed it — an answer from Presto, or a capture
that verifies. Add the capture.
